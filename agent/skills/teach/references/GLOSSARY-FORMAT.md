# GLOSSARY.md Format

`GLOSSARY.md` lives at the workspace root. It is the canonical vocabulary for this topic, written in the user's own words once they genuinely understand each term. Every lesson and reference document must adhere to it — once a term is defined here, never use a synonym or a different definition where the entry applies.

## Template

```md
# {Topic} Glossary

## Terms

- **{Term}** — {One-line definition in the user's own words. Add a second line only when a non-obvious example or caveat is worth recording.}
- **{Term}** — {…}
```

## Rules

- **One glossary per workspace.** It is shared across every lesson and reference document.
- **Write terms only after understanding.** Do not seed it from a textbook — capture a term once the user can use it correctly. This is the same bar as a learning record.
- **The user's own words.** A definition copied verbatim is a sign the term isn't really learned yet. Paraphrase.
- **Authoritative.** When a lesson needs a term, link to its glossary entry rather than re-defining it inline. If a term isn't here yet, add it.
- **Revise, don't duplicate.** When understanding deepens, update the existing entry. If an earlier definition was wrong, note the correction (and consider writing a learning record capturing the misconception).
- **Keep it scannable.** Alphabetise the terms, keep definitions to one line, and split into sections only if the vocabulary is large enough to need it.
