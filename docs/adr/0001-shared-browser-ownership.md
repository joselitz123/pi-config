# Centrally enforce ownership in the shared automation browser

Pi sessions and herd leaves share one persistent automation browser and website login state, but each session exclusively owns the tabs it operates on. Use one Chrome MCP upstream behind a private local broker, with caller identities supplied by Pi rather than model arguments, atomic tab creation/handoff, and rejection of raw Chrome calls through the adapter. Independent isolated profiles would lose shared sign-ins; page-ID routing or rmcp-mux alone would share/route calls without enforcing ownership. We accept maintaining a reviewed tool allowlist and a pinned upstream version in exchange for predictable cross-session routing; individual commands are serialized, and the guard is explicitly not a browser or OS sandbox.
